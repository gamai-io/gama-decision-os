Problem

Tri pitanja na koja agent stack obično nema odgovor

Agenti više ne samo predlažu — oni izvršavaju: zovu SQL, šalju mail, mijenjaju stanje, prave fakture.

1. Smije li ovo uopšte da se izvrši?

Rizik, namjera i očekivani dokaz moraju biti poznati prije poziva alata — ne poslije.

2. Gdje se tačno izvršava?

Blast radius se bira po riziku: container, gVisor ili mikro-VM. Nepouzdan kod nikad golo.

3. Kako znamo da je uspjelo?

Ne po modelovom ok:true, nego po nezavisnoj provjeri i potpisanom receiptu.

// prije LLM ──▶ tool ──▶ "done" ──▶ vjeruj mi // poslije LLM ──▶ L0 ──▶ sandbox ──▶ evidence ──▶ done / rollback

Integracija

Envelope koji agent dobije prije alata

Odluka je običan JSON: tier, verdict, razlog, preporučeni sandbox i specifikacija dokaza koji mora uslijediti.

Python

Jezgro je jedan modul; nema obaveznog clouda ni baze da bi se dobila prva odluka.

import gama_decision_l0 as D0 env = D0.decide_request( "pošalji mail kupcu ALFA sa ponudom" ) # env["tier"] -> "SEND" # env["verdict"] -> "ask" # env["expected_evidence_spec"] # {"kind": "external_send", ...} receipt = D0.verify_evidence(env, "mail", result) # receipt["verified"] == True tek uz dokaz
