Stub 03 · GAMACODE

Agent koji ima ruke — i granice

GAMACODE je harness: jedan Python proces koji drži agent loop, 294 alata, pristup floti, read-only SQL, sandbox i verifikaciju. Radi kao samostalni server, kao OpenCode provajder i kao MCP izvor alata. Verzija 1.2.2.

Rizik bira sandbox

Firecracker

Pun boot 1.846 s, snapshot restore 2.28 ms. Mikro-VM u lab mreži preko fctap0; bez NAT-a na hostu.

gVisor

Sentry presreće syscall-e; sporiji je i do 13× na mikro-benchu, ali drastično smanjuje blast radius za nepoznat kod.

Mjerenja: vmlab (10 vCPU / 33 GB / GTX 1660S), 2026-10-31. Apsolutni brojevi zavise od kernela i hardvera; odnos je ono što je stabilno. Detalji su u Benchmark tabelama.

Stub 04 · BRAIN

Dijeljena memorija, ne zajednički kontekst

Agenti uče jedni od drugih kroz provjerene činjenice i lekcije — sa izvorom i mogućnošću da se zastarjela činjenica označi.

Kako radi

  • brain_search — hibridna pretraga (FTS + vektor, RRF fuzija)
  • brain_write — fact (trajna tema) ili lesson (dnevnik)
  • brain_flag — stale / wrong / verified
  • scope: global, user, room — privatno ostaje privatno
  • izvor i vrijeme uz svaki zapis

Zašto je bitno

Agent koji zaboravi proceduru pravi istu grešku svaki put. Memorija sa provenance-om skraćuje put do tačnog broja, procedure ili para — i jasno kaže kada nešto nije provjereno.

# prije rada brain_search("PDV 17 postupak") # poslije provjere brain_write("pdv-bih", "stopa 17%, rok …", kind="fact") # kada činjenica zastari brain_flag("pdv-bih", "stale")

BRAIN ne tvrdi da je sve u memoriji tačno. Tvrdi da se zna odakle dolazi i da se netačno može označiti i povući. Bez toga je dijeljena memorija samo brži način da se greška proširi.

Integracije

OpenCode, MCP i CLI

Harness se registruje kao provajder modela i kao MCP server sa alatima; isti token i ista politika važe za sve ulaze.

OpenCode

Harness je OpenAI-kompatibilan endpoint; modeli se biraju po imenu iz kataloga. Streaming i tool-call rade kroz isti loop.

MCP

Alati se izlažu po allowlisti. MCP klijent ne dobija pristup cijeloj mašini — samo onim alatima koje ste eksplicitno uključili.

CLI

Jedan ulaz za sve: gama ask, gama hc, gama find, gama doctor. Svaka komanda podržava --json za agente.

Broj alata (294) je izmjeren iz registra u gama_harness.py za 1.2.2. Broj vidljivih alata po sesiji je manji jer se dio učitava odloženo (deferred tools) — to je izvor smanjenja prompta od 86 %.

Prvi korak

Tri komande do prvog dokaza

Jezgro je lokalno. Za prvi /health nije potreban API ključ modela; za chat jeste (LLM endpoint u konfiguraciji).

01

Pokreni harness

Iz foldera repozitorija. Port se čita iz konfiguracije, default je 7125.

python3 gama_harness.py # log: GAMA Harness start port=7125 …
02

Provjeri zdravlje

Očekivan odgovor je JSON sa ok:true i verzijom.

curl -sS http://127.0.0.1:7125/health {"ok": true, "ver": "1.2.2", "ts": 1794609895}
03

Pošalji zadatak

Loopback može biti zaključan tokenom; tada ide X-Token header.

curl -sS http://127.0.0.1:7125/chat \ -H "Content-Type: application/json" \ -H "X-Token: $GAMA_TOKEN" \ -d '{"text":"koliko ima kupaca u bazi","sid":"demo-1"}'

Četvrti korak — provjera dokaza — je na stranici Verifikacija i u sekciji Dokumentacija ispod.

Dokumentacija

Quickstart i ključne rute

Jezgro je lokalno; za chat je potreban LLM endpoint u konfiguraciji. Sve rute primaju i vraćaju JSON.

Ključne rute

  • GET /health, GET /metrics
  • POST /chat — jedan odgovor
  • POST /stream/ticket + GET /stream — SSE
  • POST /session/upload — fajlovi, slike, audio
  • POST /gtl/verify — verifikacija receipts
  • GET /ui — web interfejs

Konfiguracija (env)

  • GAMA_HARNESS_TOKEN / GAMA_REQUIRE_TOKEN_LOOPBACK=1 — auth
  • GTL_SIGN_KEY / GTL_SIGN_PUB — Ed25519 par
  • GTL_CHAIN_KEY — HMAC za hash-lanac
  • GTL_RECEIPT_DB — lokacija ledger baze
  • BH_SPECULATIVE_TIMEOUT — budžet spekulativnog koraka (default 0.15 s)
Sigurnost prije svega: ne izlažite harness na javni internet bez TLS-a, tokena i reverse proxyja. Podrazumijevani režim je lokalni/serverski, single-tenant. Za produkciju koristite systemd/Docker iz dokumentacije i odvojene tokene po klijentu.

Puna dokumentacija, MCP konfiguracija i primjeri su u Dokumentaciji i MCP stranicama.
